# RAG Chat 改造方案书

**版本**：v1.0（2026-10-17）
**范围**：账号体系、浅色前端、按用户问答日志
**不在本期**：公网部署实施、admin 页面改版、Redis 历史按会话拆分

---

## 一、背景与问题

RAG Chat 目前是一个单文件深色前端（`rag_chat/static/chat.html`）+ FastAPI 后端。要把它变成一个可以发给别人使用的链接，现有设计有四个必须解决的问题：

1. **密钥暴露**：用户需要在左侧输入 API Key，这把 key 同时是服务端鉴权口令和 DeepSeek 调用密钥。任何人拿到它就能直接消耗额度；前端代码里也围绕它堆了弹窗、记住、移动端提示等一堆逻辑。
2. **没有账号**：`user_id` 由浏览器生成、还能手动改，Redis 多轮记忆和日志都按它归属。换个人改个名字就能串到别人的上下文。
3. **日志不可查**：问答记录只追加到 `chat_logs.txt`，没有思考过程、工具调用参数和耗时，出问题只能靠翻文本。
4. **界面不符合使用场景**：黑蓝红深色主题偏演示风格，左栏重点是填 key 而不是对话；历史记录平铺，没有时间分组。

---

## 二、改造目标

| 目标 | 验收标准 |
|---|---|
| 账号体系 | 用户名（2-10 个英文字母，唯一，大小写不敏感）+ 密码（至少 8 位）注册登录；未登录不能进入聊天页 |
| 密钥归位 | 浏览器不再出现 API Key；DeepSeek 调用统一使用服务端 `.env` |
| 身份可信 | 服务端从会话取用户身份，前端伪造的 `user_id` 无效 |
| 浅色界面 | 聊天区白底黑字；侧边栏按给定设计还原（280px、浅灰、时间分组、底部用户区） |
| 可排障 | 每次问答落库：问题、答案、思考步骤、工具调用（参数/结果/耗时）、来源、错误、耗时、request_id |
| 成本可控 | 每账号每日消息限额（默认 50，可配置） |
| 可部署 | 页面、会话、静态资源都为同源部署设计，ngrok / 单机 VPS 可直接用 |

## 三、总体方案

```
┌─────────────────────────────┐
│ web/login.html              │  未登录 → /login
│ 登录 / 注册（同页切换）      │
└──────────────┬──────────────┘
               │ POST /api/register | /api/login
               │ ← Set-Cookie: rag_session（HttpOnly, SameSite=Lax）
               ▼
┌─────────────────────────────┐
│ web/chat.html + static/js/* │  登录后 → /
│ 侧边栏 / 对话区（Tailwind）  │
└──────────────┬──────────────┘
               │ POST /chat（携带 cookie，无 API Key）
               ▼
┌──────────────────────────────────────────────┐
│ app_fastapi.py                               │
│  require_user → 每日额度 → run_agent_sse     │
│      └─ AgentLoop(api_key=服务端 .env)       │
│      └─ QATrace 收集思考/工具/来源            │
└──────────────┬───────────────────────────────┘
               ▼
        rag_chat/data/rag_app.db
        users / usage_daily / qa_audit
```

### 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 用户与日志存储 | SQLite（Python 标准库 `sqlite3`） | 单机、低并发、零额外服务；已有 `campus_scraper/storage.py` 先例 |
| 密码哈希 | bcrypt（cost 12，先 SHA-256 再 base64） | 已随依赖安装；规避 bcrypt 72 字节上限 |
| 登录态 | HMAC 签名的 HttpOnly Cookie | 不引入 JWT/itsdangerous 依赖；服务端可查库撤销 |
| 前端 | 原生 HTML + Tailwind CSS v4 + ES Modules | 不引入 React/Vite；Tailwind CLI 生成静态 CSS，部署时无需 Node |
| 图标 / Markdown | lucide UMD / marked UMD，本地托管 | 不依赖 CDN，国内网络更稳 |
| 页面托管 | `web/` 只经路由提供，`static/` 只放公开资源 | 避免 `/static/chat.html` 绕过登录 |

## 四、详细设计

### 4.1 账号体系

**数据表**

```sql
users(
  id, username, username_norm UNIQUE, password_hash,
  created_at, last_login_at, session_version, disabled
)
usage_daily(user_id, day, count, PRIMARY KEY(user_id, day))
```

- 用户名校验 `^[A-Za-z]{2,10}$`，原始大小写用于显示，`username_norm = lower()` 保证 `Alice` 与 `alice` 不可重复注册。
- 密码至少 8 位、最多 64 字符；bcrypt cost 12。
- 登录失败统一返回「用户名或密码错误」，未知用户也跑一次 dummy bcrypt，避免通过响应时间枚举账号。

**会话**

- Cookie 名 `rag_session`，`HttpOnly`、`SameSite=Lax`、`Path=/`，默认 7 天。
- Token = `base64url(payload) + "." + base64url(HMAC-SHA256)`，payload 含 `uid`、`session_version`、过期时间。
- 每次请求查库校验用户存在、未禁用、`session_version` 匹配；改密码或强制下线只需递增版本号。
- `Secure` 属性由 `COOKIE_SECURE=auto` 跟随请求协议或 `X-Forwarded-Proto`；本地 HTTP 不设 Secure（否则浏览器丢弃 cookie），ngrok 的 HTTPS 下自动设置。

**接口**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/login` | 登录/注册页；已登录跳 `/` |
| GET | `/api/auth-config` | 公开，返回密码长度、是否需邀请码 |
| POST | `/api/register` | 201，自动登录；重名 409；校验失败 422 |
| POST | `/api/login` | 200；失败统一 401 |
| POST | `/api/logout` | 清 cookie，幂等 |
| GET | `/api/me` | 当前用户 + 今日额度使用情况 |

**路由保护**

- `GET /`：无有效会话 → `303 /login?next=/`。
- `POST /chat`：`Depends(require_user)`，身份取自会话。
- `/scrape`、`/scrape/start`：仍用管理员 `X-API-Key`，不开放给普通用户。
- `/health`、`/kb-stats`、`/scrape/status`：保持公开。

### 4.2 密钥与成本

- `/chat` 从 `os.getenv("API_KEY")` 读取 DeepSeek key，交给现有 `AgentLoop`；前端不再传 key。
- **每日限额**：`DAILY_MESSAGE_QUOTA` 默认 50，`0` 关闭。在 `/chat` 入口用 SQLite 原子 UPSERT 扣减，超限返回 429「今日提问次数已达上限」。
- 计数口径：所有被接受的请求都计数（含缓存命中与生成失败），用于防滥用。
- 预留 `REGISTER_INVITE_CODE`（默认空=关闭）。如果链接被转发后额度异常，填上即可只允许持码注册。

### 4.3 前端改造

**侧边栏（280px，`#F9F9F9`）**

- Header：左侧蓝色加粗 `RAG Chat`；右侧 `Search`、`PanelLeft` 图标按钮。
- 新对话：整行白色胶囊按钮、细边框 + 轻阴影、`Plus` 图标 + 「开启新对话」。
- 历史：可滚动、隐藏滚动条；按 `updatedAt` 分组「今天 / 7 天内 / 30 天内 / 更早」；组标题 11px 浅灰 + `MoreHorizontal`（点击折叠该组）；条目单行截断、hover 浅灰底、保留删除按钮。
- 底部：圆形首字母头像、用户名、退出按钮；上方浅色分割线。
- 移动端：侧边栏变抽屉，主区 header 提供 `PanelLeft` 开关，遮罩/选中会话后关闭。

**对话区**

- 白底黑字；用户消息浅灰气泡，AI 回答无气泡、用 typography 排版。
- 来源卡片、思考过程、错误提示、代码块、表格全部改为浅色高对比。
- 保留免责声明、流式输出、来源折叠、思考折叠。

**状态与组件**

- `store.js`：localStorage 按账号隔离，键为 `rag_chat:v2:u<id>:conversations`；对话增加 `updatedAt`。
- `sidebar.js` / `render.js` / `chat.js` / `api.js` / `main.js`：分别负责侧边栏、消息渲染、SSE、请求封装与启动。
- 所有事件用 `addEventListener`，不再使用内联 `onclick`。
- 旧 `rag_chat_api_key`、`rag_chat_user_id` 在登录后清除；旧对话首次登录时询问是否导入当前账号（不自动迁移，避免共用电脑串号）。

### 4.4 按用户问答日志

**表 `qa_audit`**

| 字段 | 内容 |
|---|---|
| `user_id` / `username` | 账号归属（服务端写入，不接受前端传值） |
| `request_id` / `conversation_id` | 串联一次请求与前端会话 |
| `question` / `answer` | 完整问答 |
| `thinking_json` | 思考步骤数组 |
| `tool_calls_json` | 每次工具调用：工具名、参数、结果、成功与否、耗时、是否截断 |
| `sources_json` | 检索来源 |
| `history_json` | 本轮带给模型的历史（截断） |
| `error` / `status` | 错误信息；`done` / `error` / `aborted` |
| `mode` | `live` 或 `cache` |
| `latency_ms` / `model` / `created_at` | 排障与统计 |

**采集方式**

在 `run_agent_sse` 中维护 `QATrace`：

- `ThinkingEvent`、`ToolCallEvent`、`ToolResultEvent`、`TextEvent`、`DoneEvent` 同步更新 trace；
- 工具调用与结果按工具名 FIFO 配对，计算耗时；单条工具输出截断 20 KB；
- 缓存命中路径单独记 `mode=cache`；
- 当前 `AgentLoop` 的异常会直接抛出（不会产生 `ErrorEvent`），因此在 `try/except/finally` 中捕获，`finally` 统一落库；
- 落库失败只记日志，绝不影响对话。

**查询**

- `GET /admin/audit`：管理员 key 保护，支持按用户、时间、状态过滤。
- `GET /admin/audit/export`：导出 JSONL / CSV。
- 普通用户 cookie 无权访问审计数据。
- 现有 TXT 日志暂时保留（消融实验仍在用），数据库成为主查询来源。

## 六、验证方案

### 自动化测试

- 注册：成功、重复用户名（含大小写）、非法用户名、短密码；
- 登录：正确、错密码与未知用户返回同一文案；
- 会话：篡改签名、过期、登出后失效；
- 路由：匿名 `/` 跳登录；`/health`、`/kb-stats` 公开；`/scrape/start` 仍需管理员 key；
- `/chat`：未登录 401；伪造 `user_id` 被忽略；超限 429；
- 审计：正常、异常、缓存三条路径都落库，字段完整；落库失败不影响对话。

运行：`cd rag_chat && ../.venv/Scripts/python.exe -m pytest tests/ -v`

### 手动验收

1. `cd rag_chat && npm install && npm run build`
2. `../.venv/Scripts/python.exe -m uvicorn app_fastapi:app --host 127.0.0.1 --port 8000 --proxy-headers --forwarded-allow-ips=*`
3. 注册 `alice` → 进入聊天 → 侧栏头像与用户名正确；
4. 提问：思考、来源、流式文本、完成事件正常；
5. 刷新：历史仍在；换 `bob`：列表为空；换回 `alice`：历史恢复；
6. 匿名访问 `/` 与直接访问旧的 `/static/chat.html` 都不能进入；
7. 手机宽度：侧栏变抽屉；
8. ngrok：HTTPS 下 cookie 带 `Secure`，刷新仍登录；
9. 查 `qa_audit`：本轮问题、答案、思考、工具调用、耗时齐全。

> 环境注意：必须使用根目录 `.venv` 的 Python；只启动一个实例；访问用 `127.0.0.1` 而非 `localhost`。

## 七、风险与边界

| 风险 | 说明与应对 |
|---|---|
| DeepSeek 成本 | key 归服务端后，所有登录用户都花你的额度；默认 50 次/天限额，必要时开邀请码 |
| 会话密钥 | `SECRET_KEY` 未配置时用进程内随机值，重启会掉登录；部署前必须写进 `.env` |
| 历史只在本地 | localStorage 方案下换设备看不到历史（已确认接受） |
| 审计含隐私 | 问答原文入库；`app.db` 已被 gitignore，默认永久保留，后续可加保留天数 |
| 单实例限制 | SQLite + 进程内爬虫锁决定只能跑一个 uvicorn 实例 |
| admin 页面 | 本期不改，仍是深色 + API Key；与用户账号体系并存 |
| 部署 | ngrok 免费版重启换域名；固定链接需 VPS 或 Cloudflare Tunnel，后端带 torch/Chroma 必须常驻，不适合 serverless |
